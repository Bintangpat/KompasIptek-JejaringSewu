## 2. Pengembangan Fitur & Mekanisme Teknis

### 2.1 Resolusi Batasan Basis Data & Seeding Super Admin
- **Tujuan Teknis:** Mendaftarkan kredensial resmi akun `Bintang SuperAdmin` ke dalam database tanpa melanggar kendala unik PostgreSQL (`User_phoneNumber_key` dan `User_nikHash_key`).
- **Mekanisme & Alur Kerja:**
  - Sesuai arahan, pembuatan akun Admin BUMDes ganda ditiadakan untuk mengeliminasi benturan NIK dan nomor telepon yang sama.
  - Akun `Bintang SuperAdmin` didaftarkan secara presisi dengan NIK terenkripsi AES-256-GCM (`nikEncrypted`), SHA-256 HMAC index hash (`nikHash`), nomor WhatsApp `087888316935`, peran `Role.SUPER_ADMIN`, dan kata sandi di-hash menggunakan Argon2id (`Bintang Admin123!`).
- **Berkas Terkait:**
  - [`Backend/prisma/seed.ts`](file:///D:/Projects/KompasIptek/Backend/prisma/seed.ts): Injeksi data awal akun Super Admin utama terikat pada master pekon Kabupaten Pringsewu.
  - [`Backend/prisma/schema.prisma`](file:///D:/Projects/KompasIptek/Backend/prisma/schema.prisma): Penambahan field enterprise soft delete `isDeleted` dan `deletedAt`.

### 2.2 Endpoint Manajemen Pengguna Enterprise Terpusat
- **Tujuan Teknis:** Menyediakan layanan CRUD lengkap, ekspor, backup snapshot, dan batch import berstandar tata kelola enterprise.
- **Mekanisme & Alur Kerja:**
  - `GET /api/v1/users/admin/all`: Mendukung query pagination (`page`, `limit`), pencarian teks (*insensitive search* pada nama, HP, email), serta filter terisolasi (`role`, `pekonId`, `isDeleted`, `isNikVerified`).
  - `PATCH /api/v1/users/admin/:id`: Memperbarui seluruh properti esensial pengguna. Jika akun di-soft delete, sistem otomatis mencabut (*revoke*) seluruh sesi aktif pengguna pada tabel `UserSession`.
  - `DELETE /api/v1/users/admin/:id`: Soft delete terproteksi transaksi atomik untuk mencegah perusakan riwayat buku besar keuangan (*LedgerEntry*).
  - `POST /api/v1/users/admin/import`: Pemrosesan baris massal di dalam blok `try-catch`. Setiap baris divalidasi terhadap NIK 16-digit dan regex nomor WhatsApp. Tabrakan duplikat pada NIK, HP, atau email diskip secara anggun (*gracefully skipped*) dan dicatat ke dalam array `skippedDetails` dengan pesan kegagalan eksplisit.
  - `GET /api/v1/users/admin/export`: Serialisasi data seluruh pengguna beserta saldo dompet untuk kebutuhan pelaporan dinas.
  - `POST /api/v1/users/admin/backup`: Menghasilkan snapshot JSON lengkap seluruh pengguna dan pekon yang disegel dengan checksum SHA-256 untuk pemulihan bencana (*Disaster Recovery*).
- **Berkas Terkait:**
  - [`Backend/src/features/users-wallet/dto/users.dto.ts`](file:///D:/Projects/KompasIptek/Backend/src/features/users-wallet/dto/users.dto.ts): DTO validasi `AdminUpdateUserDto`, `AdminQueryUsersDto`, `AdminImportUsersDto`.
  - [`Backend/src/features/users-wallet/users-wallet.service.ts`](file:///D:/Projects/KompasIptek/Backend/src/features/users-wallet/users-wallet.service.ts): Logika bisnis manajemen pengguna, deteksi duplikat, dan enkripsi NIK.
  - [`Backend/src/features/users-wallet/users.controller.ts`](file:///D:/Projects/KompasIptek/Backend/src/features/users-wallet/users.controller.ts): Controller terproteksi `@Roles(Role.SUPER_ADMIN)` dan `JwtAuthGuard`.

## 4. Dampak Basis Data & Skema (Database & Migration Impact)

- **Perubahan Skema:**
  - Menambahkan kolom `isDeleted: Boolean @default(false)` pada model `User`.
  - Menambahkan kolom `deletedAt: DateTime?` pada model `User`.
- **Status Migrasi:** Sinkronisasi skema basis data dijalankan menggunakan `prisma db push` dan Prisma Client v5.22.0 digenerate ulang.
- **Backward Compatibility:** 100% kompatibel ke belakang karena nilai default `isDeleted` adalah `false` dan `deletedAt` bernilai `null` untuk seluruh baris data eksisting.

  - Format response impor: `{ totalProcessed: number, successCount: number, skippedCount: number, skippedDetails: SkippedUserDetail[], message: string }`.
- **Status Kompatibilitas:** Fully Backward Compatible. Rute eksisting pengguna biasa (`/users/me`, `/users/unverified`) tetap berfungsi tanpa perubahan kontrak.

## 6. Keamanan, Integritas Data & Validasi

- **Pola Transaksi:** Transaksi atomik `this.prisma.$transaction(...)` diterapkan pada soft-delete (pencabutan sesi + pembaruan status) dan pembuatan user + wallet pada fungsi batch import.
- **Integritas Buku Besar (Ledger):** Penghapusan akun secara fisik (*Hard Delete*) dilarang keras demi menjaga referensi foreign key pada `Wallet` dan `LedgerEntry`. Sistem menerapkan Soft Delete.
- **Validasi Input:** Menggunakan `class-validator` (`IsString`, `IsEnum`, `IsUUID`, `Matches(/^[0-9]{16}$/)`, `ValidateNested`).

## 8. Strategi Rollback & Mitigasi Risiko (Disaster Recovery)

- **Langkah Rollback Kode:** `git checkout HEAD~1 -- Backend/`
- **Langkah Rollback Data:** Kolom `isDeleted` dan `deletedAt` bersifat *non-destructive nullable/defaulted*. Jika diperlukan rollback skema, kolom tersebut dapat di-drop via migrasi SQL tanpa memengaruhi data transaksi pengguna.
