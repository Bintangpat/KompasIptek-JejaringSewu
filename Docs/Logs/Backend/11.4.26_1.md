## 1. Alasan Pengembangan
> **Catatan Penting:** Bagian ini HARUS SINGKAT (maksimal 2–3 kalimat langsung pada inti masalah/kebutuhan bisnis).

Menyediakan sistem pengiriman OTP cerdas yang adaptif terhadap platform klien pemanggil (Mobile vs Web) dengan mekanisme *failover* otomatis dari notifikasi push FCM ke email Resend saat terjadi galat pada perangkat seluler, serta menjamin pengujian lokal tidak terblokir selama masa propagasi verifikasi DNS domain melalui mode simulasi dev (*graceful mock fallback*).

---

## 2. Pengembangan Fitur & Mekanisme Teknis

### 2.1 ResendProvider & Template HTML OTP Transaksional
- **Tujuan Teknis:** Menyediakan layanan pengiriman email transaksional modern menggunakan SDK resmi `resend` dengan template HTML responsif bernuansa Pekon Digital.
- **Mekanisme & Alur Kerja:** Menginisialisasi `new Resend(apiKey)`. Jika `RESEND_API_KEY` belum dikonfigurasi atau domain masih menunggu propagasi DNS, provider otomatis mengaktifkan mode simulasi dev (*fail-safe delivery*) yang mencetak kode OTP langsung ke log server sehingga proses pengujian otentikasi tidak pernah macet.
- **Berkas Terkait:**
  - [`Backend/src/features/notifications/providers/resend.provider.ts`](file:///D:/Projects/KompasIptek/Backend/src/features/notifications/providers/resend.provider.ts): Layanan pengiriman email Resend dan generator template HTML.
  - [`Backend/src/features/notifications/notifications.module.ts`](file:///D:/Projects/KompasIptek/Backend/src/features/notifications/notifications.module.ts): Registrasi dan ekspor `ResendProvider`.

### 2.2 Smart OTP Outbox Processor
- **Tujuan Teknis:** Mengatur perutean pengiriman OTP secara asinkron melalui antrean BullMQ berdasar platform pemanggil dengan mitigasi kegagalan push notification.
- **Mekanisme & Alur Kerja:**
  - **Rute Web (`platform: 'web'`):** Langsung mengirimkan OTP ke alamat email pengguna via `ResendProvider` tanpa memanggil FCM.
  - **Rute Mobile (`platform: 'mobile'`):** Memeriksa token FCM pengguna. Jika token tersedia, mencoba mengirim push notifikasi via `FcmProvider`. Jika token tidak ada atau pengiriman FCM melempar galat (*expired token, network timeout, error status*), sistem menangkap galat tersebut dan secara otomatis mengalihkan pengiriman ke email fallback via `ResendProvider`.
- **Berkas Terkait:**
  - [`Backend/src/features/notifications/processors/outbox.processor.ts`](file:///D:/Projects/KompasIptek/Backend/src/features/notifications/processors/outbox.processor.ts): Worker antrean outbox dengan logika failover.
  - [`Backend/src/features/notifications/providers/fcm.provider.ts`](file:///D:/Projects/KompasIptek/Backend/src/features/notifications/providers/fcm.provider.ts): Validasi ketersediaan token perangkat pada pengiriman OTP.

### 2.3 Deteksi Platform & DTO Auth
- **Tujuan Teknis:** Mendeteksi asal klien (Web vs Mobile) dari request payload maupun header HTTP standar.
- **Mekanisme & Alur Kerja:** `AuthController` mengekstrak platform dari `dto.platform` atau header `X-Client-Platform`. Data ini dimasukkan ke dalam payload `OutboxEvent` bersama `email` dan `fcmToken` pengguna agar dieksekusi secara akurat oleh worker.
- **Berkas Terkait:**
  - [`Backend/src/features/auth/auth.controller.ts`](file:///D:/Projects/KompasIptek/Backend/src/features/auth/auth.controller.ts): Ekstraksi header `x-client-platform` pada `register`, `sendOtp`, dan `forgotPassword`.
  - [`Backend/src/features/auth/auth.service.ts`](file:///D:/Projects/KompasIptek/Backend/src/features/auth/auth.service.ts): Penyesuaian pembuatan event outbox berisikan metadata platform dan pesan respons dinamis.
  - [`Backend/src/features/auth/dto/auth.dto.ts`](file:///D:/Projects/KompasIptek/Backend/src/features/auth/dto/auth.dto.ts): Penambahan validasi opsional `platform?: 'mobile' | 'web'` pada `SendOtpDto` dan `RegisterDto`.

  - `POST /api/v1/auth/otp/send`
  - `POST /api/v1/auth/register`
  - `POST /api/v1/auth/password/forgot`
- **Perubahan DTO:**
  - Menambahkan field opsional `platform?: 'mobile' | 'web'` pada `SendOtpDto` dan `RegisterDto`.
  - Mendukung header `X-Client-Platform: mobile | web`.
- **Status Kompatibilitas:** **100% Backward Compatible**. Klien lama yang tidak mengirimkan field atau header ini akan otomatis di-fallback ke platform default `mobile`.

## 6. Keamanan, Integritas Data & Validasi

- **Penyembunyian Kredensial:** Variabel `RESEND_API_KEY` dan `EMAIL_FROM` disimpan terisolasi di berkas `.env`.
- **Graceful Error Handling:** Galat API pihak ketiga (Resend maupun Firebase) ditangkap secara terkontrol tanpa menyebabkan unhandled rejection atau *crash* pada worker server.
- **Anti-Spam & Rate Limiting:** Endpoint pengiriman OTP tetap dilindungi guard throttler `@Throttle({ medium: { limit: 3, ttl: 300000 } })` (maksimal 3 permintaan per 5 menit).

## 8. Strategi Rollback & Mitigasi Risiko (Disaster Recovery)

- **Langkah Rollback Kode:** Jika integrasi Resend perlu dinonaktifkan sementara, kosongkan nilai `RESEND_API_KEY` di `Backend/.env`. Provider akan secara otomatis beralih ke mode simulasi log terminal tanpa memutus alur pendaftaran warga.
- **Mitigasi Masa Transisi DNS:** Pengembang dapat langsung menguji alur otentikasi secara lokal tanpa harus menunggu propagasi DNS domain selesai karena mode simulasi mencetak kode OTP langsung di konsol NestJS.
